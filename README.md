# RangerDOM

A web page's scripts with a DOM, without a browser. One JavaScript engine
([CEr](https://github.com/terotests/componentengine), the evaluator of
ComponentEngine as a strict Rust module) holds one page, and a
[Ranger](https://github.com/terotests/Ranger) class drives it, so the same
source builds to JavaScript, C++ and the other Ranger targets. React 18
runs on it (`tests/RealmTest.rgr`), as do Preact, Vue and Chart.js on the
same `webapi.js` elsewhere.

| File | Role |
| --- | --- |
| `js/prelude.js` | the window, timers on the host's clock, the outbox (console, `window.open`, fetch requests) |
| `js/webapi.js` | the DOM: nodes, events, selectors, innerHTML, focus, forms, the CSS cascade and `getComputedStyle`, observers, storage, `fetch` / XHR over the host, a 2D canvas |
| `js/host.js` | the page as HTML again (`__snapshot`), a GET form's default action |
| `src/DomScripts.rgr` | the three as Ranger strings, generated by `tools/gen-scripts.mjs` |
| `src/DomRealm.rgr` | the realm: start, run the scripts, input, tick, resources, snapshot, messages |

`webapi.js` comes from [terotests/MFilesAPI](https://github.com/terotests/MFilesAPI)
(`web/dom/js`), where it runs UI extension pages; nothing here depends on
that project.

## Using it

In a Ranger project's `ranger.json`:

```json
"rangerdom": {
  "git": "https://github.com/terotests/RangerDOM.git",
  "rev": "<commit>"
}
```

`rgrc install` brings CEr with it. Then:

```ranger
Import "pkg:rangerdom/src/DomRealm.rgr"

def r (new DomRealm())
r.addScript("https://example.com/app.js" appText)   ; external scripts, fetched by the host
r.start(html "https://example.com/" 1024.0 768.0)
r.runScripts()                                     ; classic, then deferred; DOMContentLoaded, load
def html:string (r.snapshot())                     ; every element has data-rd="<id>"
r.input("{\"type\":\"down\",\"target\":12}")         ; webapi.js hostInput: down, up, key, text, set, focus, scroll
r.input("{\"type\":\"up\",\"target\":12}")
r.tick(16.0)                                       ; the host's clock moved on
if (r.changed()) { html = (r.snapshot()) }
def msgs:string (r.messages())                     ; [{"tag":"open"|"fetch"|"console"|"error", …}]
r.resource(1 200 body "application/json")          ; the answer to {"tag":"fetch","id":1}
```

The realm reaches nothing itself: no network, no files, no windows. A
link's click, `window.open`, a GET form and every fetch come out as
messages, and the host decides what to do with them.

Not there: ES modules that import (a module script runs as a classic one,
so a bundle that imports nothing runs), generators and `eval` (CEr has
neither yet), layout (the host lays the page out and may tell the realm
where its boxes are with `layout`).

## Building and testing

```sh
npm install           # ranger-compiler, and CEr into vendor/ (rgrc install -vendor)
npm test              # tests/RealmTest.rgr on Node
npm run test:cpp      # the same through C++
node tools/gen-scripts.mjs   # after changing js/*.js
```
