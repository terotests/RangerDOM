# RangerDOM

A web page's scripts with a DOM, without a browser. One JavaScript engine
([CEr](https://github.com/terotests/componentengine), the evaluator of
ComponentEngine as a strict Rust module) holds one page, and a
[Ranger](https://github.com/terotests/Ranger) class drives it, so the same
source builds to JavaScript, C++ and the other Ranger targets. React 18
runs on it (`tests/RealmTest.rgr`), as do Preact, Vue and Chart.js on the
same `webapi.js` elsewhere.

Try it in the browser: the [playground](https://terotests.github.io/RangerDOM/)
shows UI library pages in Chrome and in RangerDOM side by side.

| File | Role |
| --- | --- |
| `js/prelude.js` | the window, timers on the host's clock, the outbox (console, `window.open`, fetch requests) |
| `js/webapi.js` | the DOM: nodes, events, selectors, innerHTML, focus, forms, the CSS cascade and `getComputedStyle`, observers, storage, `fetch` / XHR over the host, a 2D canvas |
| `js/host.js` | the page as HTML again (`__snapshot`), a GET form's default action |
| `src/DomScripts.rgr` | the three as Ranger strings, generated by `tools/gen-scripts.mjs` |
| `src/DomRealm.rgr` | the realm: start, run the scripts, input, tick, resources, snapshot, messages |

`webapi.js` is kept here: projects that use RangerDOM pin this repository
and take `webapi.js` from it, so change it here. Nothing here depends on
those projects.

Besides the HTML snapshot, `webapi.js` gives the page as a render tree for a
host that lays it out itself: `__render()` is every box with its computed
style as JSON, and the host draws that (for example with EVG, as the
[playground](https://terotests.github.io/RangerDOM/) does).

## Using it

In a Ranger project's `ranger.json`:

```json
"rangerdom": {
  "git": "https://github.com/terotests/RangerDOM.git",
  "rev": "<commit>"
}
```

`rgrc install` brings CEr with it. Then:

```ranger
Import "pkg:rangerdom/src/DomRealm.rgr"

def r (new DomRealm())
r.addScript("https://example.com/app.js" appText)   ; external scripts, fetched by the host
r.start(html "https://example.com/" 1024.0 768.0)
r.runScripts()                                     ; classic, then deferred; DOMContentLoaded, load
def html:string (r.snapshot())                     ; every element has data-rd="<id>"
r.input("{\"type\":\"down\",\"target\":12}")         ; webapi.js hostInput: down, up, key, text, set, focus, scroll
r.input("{\"type\":\"up\",\"target\":12}")
r.tick(16.0)                                       ; the host's clock moved on
if (r.changed()) { html = (r.snapshot()) }
def msgs:string (r.messages())                     ; [{"tag":"open"|"fetch"|"console"|"error", …}]
r.resource(1 200 body "application/json")          ; the answer to {"tag":"fetch","id":1}
```

The realm reaches nothing itself: no network, no files, no windows. A
link's click, `window.open`, a GET form and every fetch come out as
messages, and the host decides what to do with them.

Not there: ES modules that import (a module script runs as a classic one,
so a bundle that imports nothing runs), generators and `eval` (CEr has
neither yet), layout (the host lays the page out and may tell the realm
where its boxes are with `layout`).

## The page in EVG (Rust crates)

Three Cargo crates, written in the Rust Ranger reads, so cargo and every
Ranger target build them:

| Crate | Role |
| --- | --- |
| `json/` (`rangerdom_json`) | `JsonParser` / `JsonValue`: the tree `__render()` gives, and `DomText` |
| `view/` (`rangerdom_view`) | `DomView`: that tree as [EVG](https://github.com/terotests/evg) elements, laid out and drawn by EVG on any host (SDL, Kotlin, Go or Rust WASM, EVGBrowser); `DomMemo` keeps the elements and their layout from frame to frame, so a frame costs what changed |
| `style/` (`rangerdom_style`) | `DomStyle`: selector matching for webapi.js on the host side, any JS engine. The host routes `__hostSync` requests that start with U+0001 `S` (`DomStyle::mine`) to `call`; the page turns it on with `__webdom.rsx(true)`. webapi.js describes an element when it first matches an element of its kind (sigOf), DomStyle answers the rules that match and leaves `:hover`, `:has()`, sibling combinators and the like to webapi.js. It keeps nothing the page needs: a new host (a restored snapshot) is told again. `__webdom.rsxCheck(true)` compares it with webapi.js's own matching <br>RX (`__webdom.rx(true)`, `dom_tree.rs`): the computed styles and render nodes too. webapi.js tells each changed element once (B: children, inline style, attributes; X: texts; D: rule declarations), the host styles them (`DomTree`) and builds the nodes; what it cannot (controls, pictures, svg, tables, custom properties, state selectors when asked by webapi.js...) are holes webapi.js renders (J) under the host's parent style. The page's JSON names the host's node as `{"rx": handle}`, which `DomPage` and the playground take from `DomStyle.ext`. `__webdom.rxCheck(true)` renders each frame again in webapi.js and compares. Off by default: RangerGames turns it on (`RG_DOM_RX=0` off), the playground with `PG_RX=1` |
| `view/` `DomPage` | a host's whole side of a changing page: takes `__renderDelta()` (after `__deltaRender(true)`), keeps the nodes it was sent and the elements built for them (DomMemo, keepLayout), gives `__layout` only the boxes that changed (`settle`), and takes the sizes of pictures the host fetches (http, https: `wanted`, `setImageSize`, drawn by their URL). EVGBrowser draws its script pages with it |

A host with DomPage, in Ranger:

```ranger
def p:DomPage (new DomPage())
p.setSize(w h)
def r:int (p.take((realm.eval("__renderDelta()"))))  ; -1: ask __renderDelta(1)
if (r > 0) {
    lay.layout((p.view()))                            ; in the host's own tree
    def boxes:string (p.settle())                     ; "" when none moved
    if ((strlen boxes) > 0) {
        realm.layout(("{\"boxes\":" + boxes + "}"))
    }
}
```

All name the Ranger runtime as `../../runtime/rust/ranger`, and the view
and style name `../domjson`, so a project copies them into
`<Ranger>/gallery/domjson`, `gallery/domview` and `gallery/domstyle`. Ranger
reads EVG from `lib/evg`; cargo takes it from `runtime/rust/rangerevg`.

## Building and testing

```sh
npm install           # ranger-compiler, and CEr into vendor/ (rgrc install -vendor)
npm test              # tests/RealmTest.rgr on Node
npm run test:cpp      # the same through C++
node tools/gen-scripts.mjs   # after changing js/*.js
```
